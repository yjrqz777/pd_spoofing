# 嵌入式项目分层约定

适用于 8 位与 32 位 MCU 的裸机项目，也可作为 RTOS 项目的基础分层约定。目录名与函数前缀可按项目调整，**要固定下来的是职责边界与依赖方向**，不是名称。

## 1. 四层结构

```
Application  ->  Device  ->  BSP  ->  Vendor
                  ^
              Components（横切，可被任意层使用）
```

| 层 | 一句话职责 | 判据：改什么只改这一层 |
|---|---|---|
| Application | 产品在当前条件下应该做什么 | 改业务规则、改流程、改阈值、改页面 |
| Device | 这是什么器件，以及这个器件怎样使用 | 换器件型号、换分辨率、换通信协议封装 |
| BSP | 当前 MCU 与这块 PCB 怎样操作硬件 | 换 MCU、改引脚、改外设参数与时钟 |
| Vendor | 厂商提供的启动文件、寄存器定义与外设库 | 不由项目修改，升级 SDK 不影响上面三层 |
| Components | 与产品、硬件都无关的通用代码 | 换芯片换器件都不用改 |

引脚映射表与全局配置头（如 `user_config.h`）不属于任何一层，各层都可引用；它只放**定义**，不放操作。

## 2. 每一层放什么

### 2.1 Application

放：

- 产品状态机与状态迁移
- 用户输入到行为的映射
- 采集流程、数据处理、阈值与保护策略
- 显示内容、页面布局、刷新时机
- 各周期性任务与工作流程

不放：引脚与寄存器操作、外设初始化、器件协议细节、时序参数。

### 2.2 Device

放：

- 器件的协议封装（命令序列、寄存器访问、字节序、数据格式）
- 原始数据到物理量的换算与标定
- 器件级基本动作（开、关、设置参数）
- 器件能力参数（分辨率、通道数、编号范围）
- 把一次大动作拆成多次小动作的推进状态机
- 器件上下文结构体（`static` 在模块内）

不放：引脚与 GPIO 操作、外设寄存器配置、产品规则（何时动作、告警阈值、页面内容）。

### 2.3 BSP

放：

- 系统时钟与外设时钟使能
- GPIO 引脚配置（复用、上下拉、方向、上电默认电平）
- 外设初始化与配置（串口、总线、定时器、ADC、DMA、看门狗）
- 引脚级操作与原始数据收发
- 中断服务函数与标志处理
- 时基配置与定时器资源仲裁
- 临界区原语（关/开全局中断）
- 原始数据收发接口（发字节块、读原始码值、读电平）

不放：产品状态机与告警策略、器件协议、物理量换算、页面内容。

### 2.4 Components

放：通用算法（滤波、插值、换算、校验）、通用容器（环形缓冲、队列）、日志、断言、纯数据结构、与器件无关的数据表。

约束：

- 只依赖标准库与自身，不得包含任何 BSP、Device、Application 的头文件。
- 不出现业务枚举、产品参数、引脚号。
- 它的接口只有数据进、数据出，不知道数据代表温度、电压还是颜色。

## 3. 依赖规则

1. 依赖只许向下：Application 到 Device 到 BSP 到 Vendor。
2. Components 可被任意层使用，但它自己不许反向依赖。
3. Application 只能调 Device 与 Components，不得直接调用通用外设接口（总线、ADC、定时器、DMA）。
4. 下层不得反向依赖上层。需要"下层定时被推进"时，用**函数指针注入**：上层把自己的短函数注册给下层，下层只持有函数指针，不知道它属于谁。
5. 模块之间只通过头文件接口通信，不访问其它模块的内部变量。
6. 不得为统一目录名而重构无关代码；改动应围绕职责边界进行。

## 4. 接口与头文件组织

- 一个模块一对源文件与头文件；公共头只暴露必要类型与接口，不暴露实现细节。
- 模块内部状态一律 `static` 在模块源文件内，包含结构体定义；上层拿不到句柄。
- 只有中断与主循环共享的变量才加 `volatile`；共享数据优先用单生产单消费者队列或事件位掩码传递，尽量避免关中断。
- 全局包含头只放公共宏、通用类型、任务框架与芯片库基础头，**不打包各模块头**，避免头文件互相包含成环。
- 各源文件自己包含所需的模块头；头文件保护宏与文件名一致。
- 纯算法与通用工具放 Components；只有一个使用者且只有几十行时，先留在使用处，等第二个使用者出现再上移。

## 5. 命名与层级对应

| 前缀（示例） | 所属层 | 说明 |
|---|---|---|
| `Bsp` | BSP | 引脚、外设、原始数据 |
| `Dev` | Device | 器件协议与动作 |
| `Usr` / `App` | Application | 业务与流程 |
| 无前缀或模块名 | Components | 通用函数 |

规则：

- 函数前缀必须与所在目录一致，不允许上层函数使用下层前缀。
- 宏名带模块前缀，避免出现 `CMD`、`DATA`、`RED` 这类过泛的名字。
- 模块内部变量与结构体不对外暴露；对外只有函数。
- 命名风格、类型前缀、注释格式全工程统一。

## 6. 中断、临界区与实时性

- 中断服务函数写在对应外设的 BSP 模块内（谁的外设谁负责）。
- 中断里只做：清标志、读写硬件寄存器、置状态或计数、入队或置事件位。
- 中断里不做：业务流程、日志与字符串格式化、浮点运算、阻塞等待、屏幕刷新、复杂状态机。
- 需要周期性推进的设备级逻辑，由上层注册短回调给时基，回调内只允许分频、采样与状态机推进等短操作。
- 临界区原语只在 BSP 提供；Device 与 Application 不得直接操作中断控制器或状态寄存器。
- 关中断的范围要尽可能小，只包住"读改写"这几条指令。

## 7. 资源归属

- **引脚**：定义集中在一处，配置动作在 BSP；上层只使用语义接口，不出现引脚号与端口名。
- **定时器时基**：一个定时器的时基只在一个 BSP 模块里配置，谁先配置谁决定，后到者只校验参数；使用方不得再调时基初始化。
- **通道与请求源**：外设到通道的映射通常是硬件固定的；BSP 负责登记"哪个外设占用哪个通道"，使用方不得自行挑选。
- **中断优先级**：在 BSP 初始化时统一分配，不要散落在各模块，也不要在业务代码里改。
- **缓冲区**：属于哪个器件就归哪一层的模块私有；跨层只传指针与长度，且必须约定"传输期间不允许改写"。

## 8. 常见越层的四种形态

1. **BSP 里写业务**：BSP 里出现"显示什么""什么时候报警""页面字段"这类内容。
2. **Device 里戳硬件**：器件模块里出现引脚宏、寄存器名、GPIO 读写。
3. **Application 里拼协议**：业务代码里出现命令字、时序参数、寄存器操作。
4. **下层包含上层**：BSP 包含 Device 的头；Components 依赖 BSP 或 Device。

反过来看也成立：如果某个模块同时出现两种以上的内容，它就横跨了两层，需要拆。

## 9. 判断口诀

依次问四句：

1. 这是"产品在什么条件下该做什么"吗，是则放 Application。
2. 这是"某个具体器件怎样工作"吗，是则放 Device。
3. 这是"MCU 或 PCB 引脚怎样操作"吗，是则放 BSP。
4. 换芯片、换器件都不用改吗，是则放 Components。

再补一句反向确认：**换 MCU 或改引脚要改的代码属于 BSP；换器件要改的属于 Device；改业务规则要改的属于 Application。**

## 10. 评审检查清单

- [ ] 每个源文件的包含列表里没有上层模块的头。
- [ ] 中断服务函数全部在 BSP 模块内，中断内无日志、无浮点、无阻塞。
- [ ] 器件上下文结构体定义在源文件内，公共头只有接口。
- [ ] 函数前缀与所在目录一致。
- [ ] 引脚号与端口名只出现在引脚定义文件与 BSP 中。
- [ ] Components 内没有业务枚举，也不包含任何上层头文件。
- [ ] 每个定时器时基只有一个配置点，通道占用有登记。
- [ ] 临界区原语只由 BSP 提供，上层不直接开关中断。
- [ ] 没有为了统一命名而做的无关重构。
